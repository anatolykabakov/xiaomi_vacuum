# Control: ведение по траектории

`cpp/app/src/services/control.cpp`, алгоритм — `cpp/app/src/algo/pure_pursuit.cpp` (чистый, тесты
`cpp/tests/control_test.cpp`). Один выход `controls/cmd_vel` — `vx` и `w` для дифференциального шасси.

## Вход и выход

| | топик | тип |
|---|---|---|
| вход | `planner/trajectory` | `Trajectory` |
| вход | `slam/pose` | `Pose2D` |
| вход | `sensors/odometry` | `Odometry` |
| вход | `robot/state` | `RobotState` |
| вход | `safety/stop` | `SafetyStop` |
| выход | `controls/cmd_vel` | `CmdVel` |

Тик 50 мс.

## Pure pursuit

1. Ближайшая точка траектории к роботу.
2. Точка прицела — первая после ближайшей на расстоянии `lookahead`; `lookahead` растёт со
   скоростью (`ctrl_lookahead_gain · v`) в пределах `[ctrl_min_lookahead_m, ctrl_lookahead_m]`.
3. Прицел переводится в кадр робота; кривизна `κ = 2·y_local / d²`, `w = v·κ`.
4. Скорость — минимум из скорости точки траектории, `ctrl_max_v_mps`, ограничения по кривизне
   (`max_w / |κ|`) и расстояния до цели (притормаживаем на подходе).
5. Прицел сильно сбоку или сзади (`|heading| > 1.2 рад`) — разворот на месте: `v = 0`,
   `w = ±0.6 рад/с`.
6. До цели ближе `ctrl_goal_tolerance_m` — `done`, ноль.

## Когда публикуется ноль и почему не всегда

- **Safety-стоп** активен — ноль каждый тик, перебивает и планировщик, и телеоперацию.
  Исключение — стоп только по бамперу во время ведения: `Control` откатывается назад на
  `ctrl_recover_distance_m` со скоростью `ctrl_recover_speed_mps`, сбрасывает траекторию и ждёт
  новую. К этому моменту `Slam` поставил препятствие в карту у кромки корпуса, а `Planner`
  сбросил старую траекторию, так что новая обойдёт место удара. Стоп по датчикам пола — ноль
  без отката.
- Пришла **пустая траектория** (планировщик снял цель или доехал) — один ноль.
- Траектория **старше** `ctrl_traj_max_age_ms` (2 с; планировщик перепланирует каждые 0.5 с, так
  что это означает «планировщик пропал или пишет blocked») — ноль, траектория сбрасывается.
- Цель достигнута — ноль.

В простое (нет траектории) `Control` **молчит**. Топик `controls/cmd_vel` общий с телеоперацией
из `ZmqBridge`, а у `Platform` побеждает последняя команда: публикуй мы нули в простое —
телеоперация с телефона не работала бы. Обнуление шасси при пропаже команд — обязанность
watchdog в `Platform`, не `Control`.

## Параметры

| параметр | по умолчанию | смысл |
|---|---|---|
| `ctrl_lookahead_m` | 0.30 | максимальный lookahead |
| `ctrl_min_lookahead_m` | 0.15 | минимальный lookahead |
| `ctrl_max_v_mps` | 0.25 | предел скорости |
| `ctrl_max_w_rps` | 1.0 | предел угловой скорости |
| `ctrl_goal_tolerance_m` | 0.10 | допуск достижения цели |
| `ctrl_traj_max_age_ms` | 2000 | возраст траектории, после которого стоп |
| `ctrl_recover_distance_m` | 0.10 | откат назад по бамперу; 0 — без отката |
| `ctrl_recover_speed_mps` | 0.08 | скорость отката |

## Диагностика

- Робот рыскает: увеличить `ctrl_lookahead_m` или снизить скорость.
- Робот не доезжает и крутится у цели: `ctrl_goal_tolerance_m` меньше ошибки позы; по одометрии
  без скан-матчинга 10 см — реалистичный минимум.
- Команды идут (`CMD_VEL` в логе), колёса стоят — это не Control, см. `PLATFORM.md`
  (активный режим MCU, RoboController).
