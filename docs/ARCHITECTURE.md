# Архитектура: от лидара до колёс

Вход — штатный Player робота (лидар, одометрия, гироскоп, бамперы), выход — `cmd_vel` на
дифференциальное шасси. Между ними четыре сервиса и один надзорный.

```
                 sensors/laser, sensors/odometry, sensors/imu
  ┌──────────┐ ─────────────────────────────────────────────▶ ┌──────┐
  │ Platform │                                                │ Slam │
  │ (Player) │ ◀──────────────── controls/cmd_vel ─────────┐  └──┬───┘
  └────┬─────┘                                              │     │ slam/map, slam/pose
       │ sensors/bumper, sensors/ir                    ┌────┴────┐│
       │ robot/state                                   │ Control ││
       ▼                                               └────▲────┘▼
  ┌──────────┐  safety/stop                                 │  ┌─────────┐      ┌─────────┐
  │  Safety  │ ─────────────────────────────────────────────┘  │ Planner │ ◀─── │ Mission │
  └──────────┘                                    planner/trajectory └─────────┘ goal └─────────┘
```

Сбоку — `Log` (пишет всю шину в файл) и `ZmqBridge` (граница с телефоном и ПК).

## Конвейер

| звено | сервис | вход | выход | период |
|---|---|---|---|---|
| 1. Чтение робота | `Platform` | Player :6665 | `sensors/*`, `robot/state` | rx 100 мс, state 1 с |
| 2. Карта и поза | `Slam` | `sensors/laser`, `sensors/odometry`, `sensors/imu` | `slam/pose` (на каждую одометрию), `slam/map` | карта 1 с |
| 3. Выбор цели | `Mission` | `slam/map`, `slam/pose`, `planner/state` | `planner/goal`, `mission/state` | 1 с |
| 4. Траектория | `Planner` | `slam/map`, `slam/pose`, `planner/goal` | `planner/trajectory`, `planner/state` | 500 мс, пока есть цель |
| 5. Ведение | `Control` | `planner/trajectory`, `slam/pose`, `safety/stop` | `controls/cmd_vel` | 50 мс |
| 6. Команда на колёса | `Platform` | `controls/cmd_vel` | Player position2d | tx 100 мс |
| поверх | `Safety` | `sensors/bumper`, `sensors/ir` | `safety/stop` | 50 мс |

Имена топиков объявлены в одном месте — `cpp/app/include/utils/topics.h`, типы сообщений —
в `cpp/app/include/types.h`. Одна траектория на оба канала движения: у дифференциального привода
поперечное и продольное неразделимы.

## Цикл уборки

`Mission` ведёт робота через три фазы и публикует цели планировщику:

1. **Исследование.** Сначала съезд с дока прямо вперёд. Пока на карте есть граница между
   свободным и неизвестным (фронтир), цель — ближайший достижимый фронтир. Карта растёт, пока
   фронтиры не кончатся.
2. **Покрытие.** По свободной области карты строится змейка с шагом в ширину робота и обход
   периметра вдоль стен; робот проходит маршрут целиком, планировщик ведёт между точками.
3. **Возврат.** Цель — поза старта (док). У дока миссия завершена.

Бампер по дороге: `Safety` даёт стоп, `Control` откатывается назад, `Slam` ставит препятствие в
карту, `Planner` строит новую траекторию в обход.

Подробно — `MISSION.md`. Тот же цикл целиком проверяется в симуляторе через биндинги
(`scripts/sim/run_cycle.py`).

## Middleware

Менеджер сервисов — `cpp/mw/include/mw/middleware/manager.hpp` (header-only, C++17). Каждый сервис —
класс от `mw::middleware::Service` с `configure()`, где объявляются подписки, таймеры и параметры.
У каждого сервиса свой поток; колбэки одного сервиса не пересекаются, блокировки внутри сервиса
не нужны. Параметры (`registerParameter`) меняются на ходу через менеджер. Таймеры — в миллисекундах.

## Граница с внешним миром

`ZmqBridge` — единственное место с protobuf (`proto/`). Наружу по PUB 9091 уходят
`slam/map`, `slam/pose`, `robot/state`, `planner/trajectory`, `planner/state`, `mission/state`.
Внутрь по SUB 9090 приходят `ZmqMessage{cmd_vel}` (телеоперация напрямую в `controls/cmd_vel`,
в обход планировщика), `ZmqMessage{goal}` (цель планировщику) и `ZmqMessage{mission}` (старт и
стоп уборки). Подписчик опрашивается каждые 2 мс. Записать поток с хоста — `tools/bag_record`.

Кто побеждает на колёсах: у `Platform` действует последняя полученная команда. `Control` публикует
непрерывно только пока ведёт по траектории или держит safety-стоп; в простое молчит, чтобы не
перебивать телеоперацию. Safety-стоп перебивает всех.
