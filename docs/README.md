# Документация xiaomi_vacuum

Подряд читать не нужно. Ниже — что открыть под конкретный вопрос.

## Если вы здесь впервые

1. [`ARCHITECTURE.md`](ARCHITECTURE.md) — путь от лидара до команды на колёса по звеньям и цикл
   уборки: исследование, покрытие, возврат на базу. Одна страница даёт карту системы.
2. [`ROBOT_LIMITS.md`](ROBOT_LIMITS.md) — где робот едет, а где нет. Короткая и важная: большинство
   вопросов «почему стоит» отвечается отсюда.
3. [`SYSTEM_DESIGN.md`](SYSTEM_DESIGN.md) — раскладка репозитория, соглашения кода, сборка.

## Если вы собираетесь запускать робота

| | |
|---|---|
| [`PREDRIVE.md`](PREDRIVE.md) | **чек-лист перед запуском**: место на диске робота, стек, лидар, безопасность, как остановить |
| [`SIMULATION.md`](SIMULATION.md) | прогнать полный цикл уборки в симуляторе до выезда на робота |
| [`BURN.md`](BURN.md) | прошивка, root, Valetudo, штатный `player` — как робот стал доступен по ssh |
| [`CROSS_COMPILE_CONAN_SYSROOT.md`](CROSS_COMPILE_CONAN_SYSROOT.md) | кросс-сборка под ARM; актуальный рецепт — `scripts/build_arm.sh` |

## Если вы разбираетесь, почему робот ведёт себя не так

| вопрос | документ |
|---|---|
| команда уходит, а колёса стоят; лидар пустой; робот едет медленно | [`PLATFORM.md`](PLATFORM.md) |
| робот встал и не едет, в логе `SAFETY` | [`SAFETY.md`](SAFETY.md) |
| уборка не начинается, робот не едет к неизвестному, не возвращается на базу | [`MISSION.md`](MISSION.md) |
| планировщик пишет `blocked` или траектория странная | [`PLANNER.md`](PLANNER.md) |
| поза уплывает, карта двоится | [`SLAM.md`](SLAM.md) |
| робот рыскает по траектории или не доезжает до цели | [`CONTROL.md`](CONTROL.md) |
