# Planner: траектория по карте

`cpp/app/src/services/planner.cpp`, алгоритм — `cpp/app/src/algo/path_planner.cpp` (чистый, без
middleware, покрыт тестами `cpp/tests/planner_test.cpp`). Путь строится по карте занятости от `Slam`.

## Вход и выход

| | топик | тип |
|---|---|---|
| вход | `slam/map` | `OccupancyMap` |
| вход | `slam/pose` | `Pose2D` |
| вход | `robot/state` | `RobotState` |
| вход | `planner/goal` | `Goal` (точка / док / стоп) |
| выход | `planner/trajectory` | `Trajectory` — точки `x, y, yaw, v, w, t` |
| выход | `planner/state` | `PlannerState` — `idle, no_map, planning, following, blocked, done` |

Одна траектория на оба канала: у дифференциального привода поперечное и продольное
движение неразделимы.

## Как работает

Таймер 500 мс; пока есть цель — проверяет прежнюю траекторию по актуальной карте и, если она
годится, публикует её же со свежей меткой времени; иначе перепланирует.

**Прежняя траектория годится**, если робот не дальше `plan_replan_distance_m` от неё и от
ближайшей точки до конца корпус не задевает занятых ячеек. Без этого на живой карте у стен путь
каждые полсекунды скакал между двумя вариантами обхода, и робот крутился на месте, не успевая
довернуть ни к одному. Бампер (`safety/stop` с причиной `bumper`) траекторию сбрасывает: она
вела в препятствие, которого лидар не видел, а `Slam` его уже поставил в карту.

1. **Раздувание.** Занятые ячейки расширяются на `plan_inflation_radius_m` (радиус робота
   0.1725 + 3 см), чтобы планировать движение точки, а не диска. Старт и цель часто лежат внутри
   раздувания (робот у стены, док у стены): в диске радиуса раздувания вокруг них ячейки, где
   корпус физически помещается (не ближе `robot_radius_m` + полклетки к стене), становятся
   проходимыми с множителем стоимости `escape_cost` — путь сразу уходит от стены, а не идёт
   вдоль неё.
2. **A\*** по 8-связной сетке, эвристика евклидова. Неизвестные ячейки (127) проходимы с множителем
   стоимости `plan_unknown_cost` — робот исследует, а не стоит; `plan_through_unknown=false`
   делает их непроходимыми.
3. **Прореживание** до шага `waypoint_step_m` (10 см), первая точка — сам робот, последняя — цель.
4. **Сглаживание** градиентное, с проверкой столкновений: точка, ушедшая в раздутое препятствие,
   возвращается на путь A\*. Без этой проверки срезались углы у торцов стен — тест `GoesAroundWall`
   ловит именно это.
5. **Профиль скорости.** `v ≤ plan_max_v_mps`; на изгибе `v ≤ plan_max_w_rps / κ`; к цели
   торможение `v² = 2·a·s` с `max_accel_mps2`; в конце ноль. Время `t` — интеграл `ds / v`.
   Курс в точке — направление на следующую; в последней — `goal.yaw`, если задан.

Цель достигнута, когда расстояние до неё ≤ `plan_goal_tolerance_m`: публикуется **пустая**
траектория (для `Control` это «стой») и `done`. Пути нет — `blocked`, траектория не публикуется,
и `Control` остановится сам по возрасту старой (`ctrl_traj_max_age_ms`).

## Как задать цель

Через ZMQ SUB 9090 сообщением `ZmqMessage{goal}` (`proto/robot.proto`): `type` POINT/DOCK/STOP,
`x`, `y` в метрах в кадре карты (начало — поза робота при старте `xiaomi_robot`), `yaw` и
`has_yaw`, `id`. STOP снимает цель и публикует пустую траекторию. DOCK пока равен точке.

## Параметры

| параметр | по умолчанию | смысл |
|---|---|---|
| `plan_inflation_radius_m` | 0.2025 | радиус раздувания препятствий |
| `plan_through_unknown` | true | неизвестные ячейки проходимы |
| `plan_unknown_cost` | 3.0 | штраф шага по неизвестному |
| `plan_max_v_mps` | 0.25 | скорость в профиле |
| `plan_max_w_rps` | 1.0 | угловая скорость в профиле |
| `plan_goal_tolerance_m` | 0.10 | допуск достижения цели |
| `plan_replan_distance_m` | 0.30 | робот дальше от траектории — перепланировать |

Значения по умолчанию берутся из `robot_config.h`; скорости скромные из-за медленного режима
MCU без RoboController (`PLATFORM.md`).

## Ограничения

Динамических препятствий планировщик не знает: карта меняется только лидаром и отметками
бампера (`SLAM.md`). Достижимость цели не проверяется до отправки — `Mission` сама разбирает
`blocked`.
