# Mission: цикл уборки

`cpp/app/src/services/mission.cpp`, алгоритм — `cpp/app/src/algo/cleaning_mission.cpp` с
`frontier_explorer.cpp` и `coverage_planner.cpp` (чистые, тесты `cpp/tests/mission_test.cpp`).
Сервис раз в секунду делает шаг машины состояний и отдаёт планировщику очередную цель.

## Вход и выход

| | топик | тип |
|---|---|---|
| вход | `slam/map` | `OccupancyMap` |
| вход | `slam/pose` | `Pose2D` |
| вход | `planner/state` | `PlannerState` — done/blocked по текущей цели |
| вход | `mission/command` | `MissionCommand` — `START`, `STOP`, `RETURN` |
| выход | `planner/goal` | `Goal` |
| выход | `mission/state` | `MissionState` — фаза, фронтиры, точки змейки, покрытие |

## Фазы

```
Idle ──START──▶ Exploring ──фронтиров нет──▶ Covering ──точки кончились──▶ Returning ──у дока──▶ Done
                    │                            │                             ▲
                    └────────────RETURN──────────┴─────────────────────────────┘
```

**Съезд с дока.** Первая цель — точка в `mission_undock_distance_m` (0.3 м) прямо по курсу
старта. Док стоит у стены, робот на нём внутри зоны раздувания планировщика; прямой отъезд
выводит его в свободную область без петель вдоль стены. Если планировщик не нашёл путь и к этой
точке — едем дальше без неё.

**Исследование.** Фронтир — свободная ячейка карты, у которой есть неизвестный сосед, вне зоны
раздувания. Фронтиры кластеризуются (8-связность, кластеры меньше `min_cluster_cells` — шум);
у кластера берётся ячейка, ближайшая к роботу, но не под ним (`min_distance_m`). Цель —
ближайший кластер, до которого планировщик находит путь **по известным** ячейкам. Цель считается
выполненной, когда робот подъехал (`waypoint_tolerance_m`) или когда вокруг неё в радиусе
`frontier_done_radius_m` не осталось неизвестного: граница уехала, пока ехали. Цель, к которой
планировщик трижды не нашёл путь, попадает в чёрный список (радиус `blacklist_radius_m`), и её
окрестность больше не предлагается. Фронтиры кончились — карта построена.

**Покрытие.** По итоговой карте один раз строится маршрут:
1. *Змейка* (boustrophedon): полосы вдоль X с шагом `mission_lane_width_m` (по умолчанию
   2·радиус·0.85 — перекрытие 15 %), начиная с полосы робота, затем вверх до края и вниз через
   непройденные; в каждой полосе — отрезки по подряд идущим свободным ячейкам вне раздувания,
   концы отрезков на клетку внутрь (граница раздувания на живой карте гуляет). Направление
   чередуется. Крайние полосы у стен добавляются, если до них не дошёл шаг.
2. *Периметр*: точки вдоль контура достижимой области с шагом `perimeter_step_m` (0.3 м) — вдоль
   стен и вокруг препятствий, чтобы добрать полосу, куда полосы змейки не попали.

Между точками ведёт планировщик, препятствия между ними обходятся сами. Точка, до которой пути
нет (карта уточнилась и она ушла в раздувание), один раз сдвигается к ближайшей достижимой
(`retarget_radius_m`), затем пропускается.

**Возврат.** Цель — поза старта (док). В `mission_dock_tolerance_m` от неё — `Done`. Если
планировщик не нашёл путь к доку — `Done` с пометкой «док недостижим».

## Команды

Через ZMQ SUB 9090 сообщением `ZmqMessage{mission_command}` (`proto/robot.proto`):
`START` — начать уборку с текущей позы как дока; `STOP` — остановить, планировщику уходит
`Goal{STOP}`; `RETURN` — бросить текущую фазу и ехать на док. Параметр `mission_autostart`
запускает уборку сам, как только появятся карта и поза.

## mission/state

| поле | смысл |
|---|---|
| `state` | `IDLE, EXPLORING, COVERING, RETURNING, DONE` |
| `frontiers_left` | сколько кластеров фронтиров видно |
| `waypoints_total / done` | точки маршрута покрытия (змейка + периметр) |
| `coverage_ratio` | доля известной свободной площади, пройденной корпусом (по позам на шагах миссии) |
| `detail` | почему сменилась фаза или что делаем |

## Параметры

| параметр | по умолчанию | смысл |
|---|---|---|
| `mission_autostart` | false | старт без команды, как появится карта |
| `mission_lane_width_m` | 0.293 | шаг полос змейки |
| `mission_dock_tolerance_m` | 0.25 | «на доке» |
| `mission_max_blocked_retries` | 2 | сколько blocked терпим на одной цели |
| `mission_undock_distance_m` | 0.30 | съезд с дока прямо вперёд; 0 — без него |
| `mission_perimeter_pass` | true | обход периметра после змейки |

Радиус раздувания для фронтиров и змейки — тот же, что у планировщика (радиус робота + 3 см).

## Диагностика

В логе `MISSION: ts state=N frontiers=F waypoints=D/T coverage=C detail`.

- Уборка не начинается: нет `slam/pose` или `slam/map` (см. `SLAM.md`), либо не пришла команда и
  `mission_autostart=false`.
- Робот сразу перешёл к покрытию, не исследовав: фронтиров нет — все границы известного лежат в
  зоне раздувания (узкие проёмы уже 0.5 м) или в чёрном списке.
- Покрытие пропускает целые полосы: планировщик отдаёт `blocked` по точкам змейки — смотреть,
  не уехала ли карта (дрейф одометрии, `SLAM.md`).
- `Done` с «док недостижим»: робот стоит, дальше — вручную.

Весь цикл прогоняется без робота: `docs/SIMULATION.md`.
