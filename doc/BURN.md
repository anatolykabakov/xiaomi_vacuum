# Прошивка Xiaomi Vacuum V1 (rockrobo.vacuum.v1)

Для прошивки Xiaomi Vacuum V1 (`rockrobo.vacuum.v1`) самым надёжным и современным способом является использование **DustBuilder**. Это веб-сервис, который соберёт готовую прошивку с уже встроенным **Valetudo** (управление без облака), твоим SSH-ключом и нужными звуковыми пакетами.

Ниже пошаговый план с командами для **Linux** / **macOS** (или **WSL** в Windows).

---

## Шаг 1. Подготовка ключа SSH

Тебе нужен SSH-ключ, чтобы зайти в систему робота после прошивки. Если его нет, создай:

```bash
ssh-keygen -t rsa -b 2048 -f ~/mirobot_key
```

Содержимое файла `~/mirobot_key.pub` (публичный ключ) тебе понадобится для сборки прошивки.

---

## Шаг 2. Сборка прошивки (DustBuilder)

1. Зайди на сайт [https://dustbuilder.dontvacuum.me/_v1.html](https://dustbuilder.dontvacuum.me/_v1.html).
2. Выбери модель: **Xiaomi Mi Robot Vacuum (1st Gen - rockrobo.vacuum.v1)**.
3. Вставь содержимое своего `.pub` ключа.
4. Отметь галочкой **Pre-install Valetudo** (актуальную версию).
5. Укажи свой email. Через 5–10 минут придёт ссылка на скачивание готового файла `.pkg`.

---

## Шаг 3. Установка инструментов на компьютер

Тебе понадобятся Python и библиотека **python-miio** для отправки файла роботу:

```bash
pip3 install python-miio
```

---

## Шаг 4. Получение токена (token)

1. Сбрось Wi‑Fi на роботе (зажми две верхние кнопки до фразы «Resetting Wi‑Fi»).
2. Подключись с компьютера к Wi‑Fi сети робота (название типа `rockrobo-vacuum-v1_miapXXXX`).
3. Узнай токен:

```bash
mirobo discover --handshake 1
```

4. Запиши полученный **token** и **IP** (обычно `192.168.8.1`).

---

## Шаг 5. Прошивка

**Сеть:** в сценарии после сброса Wi‑Fi (шаг 4) **оставь компьютер в Wi‑Fi сети робота** (`rockrobo-vacuum-v1_miap…`). Тогда `mirobo` достучится до **`192.168.8.1`**, а робот сможет по HTTP скачать `.pkg` с твоего ПК (оба в подсети `192.168.8.x`). Если робот уже в **домашней** Wi‑Fi и ты знаешь его IP, команду можно выполнять из домашней сети с тем IP — главное, чтобы робот **видел** компьютер по сети для загрузки файла.

Положи скачанный файл прошивки (например `v1_valetudo.pkg`) в рабочую папку и выполни:

```bash
mirobo --ip 192.168.8.1 --token ТВОЙ_ТОКЕН update-firmware v1_valetudo.pkg
```

**Что происходит:**

- В **консоли** `mirobo` после успешного `miIO.ota` печатает что-то вроде **«Update started!»**, затем полоса **прогресса загрузки** (пока робот качает `.pkg` по сети; часто порядка **1–2 минут** при нормальном Wi‑Fi).
- **Голосом** фразы вроде «Starting update» / «Update finished» **могут не произноситься** — зависит от версии прошивки и набора звуков; ориентируйся на **кольцо**, **консоль** и **ребут**.
- **Важно:** световое кольцо **мигает** во время обновления — не выключай робота. Запись образа и перезагрузка обычно занимают ещё около **5–7 минут** после окончания загрузки.
- Конец процесса: робот **перезагрузится** (сеть Wi‑Fi может на время пропасть, затем появится уже с новой прошивкой / именем **Valetudo-XXXX**).

---

## Ошибки при прошивке: откат к стоку

Если `mirobo update-firmware` падает с ошибками вроде **`Unable to parse message payload`**, **`Unable to parse json`**, **`No request was made`** — часто робот уже на **кастомной** прошивке (в `mirobo info` может быть версия вида **`v1.0_nocloud`**). На таких сборках **`miIO.ota` через `mirobo` может не работать**; повторные попытки без отката обычно бессмысленны.

**Что сделать:** вернуть **заводскую (recovery) прошивку** полным сбросом — это не то же самое, что сброс Wi‑Fi двумя верхними кнопками.

1. Открой **крышку** у робота (доступ к кнопке **Reset**).
2. **Зажми и держи** кнопку **«Домой»** (Home).
3. Не отпуская Home, **один раз нажми Reset** (скрепкой/иглой).
4. Продолжай держать Home, пока робот **голосом** не сообщит о восстановлении / сбросе (на китайских партиях — по‑китайски).
5. Дождись окончания (кольцо может **мигать** несколько минут) — **не отключай питание**. После этого снова будет **родная озвучка и сток**; при необходимости заново получи токен (`discover`) и повтори шаги прошивки **уже со стока**.

Сброс **только Wi‑Fi** (две верхние кнопки до «Resetting Wi‑Fi») **прошивку не откатывает**.

---

## Шаг 6. Проверка

1. Робот снова создаст свою Wi‑Fi сеть (уже с именем **Valetudo-XXXX**). Подключись к ней.
2. Открой браузер и перейди по адресу [http://192.168.8.1](http://192.168.8.1).
3. Ты увидишь интерфейс **Valetudo**. Здесь можно подключить робота к домашнему Wi‑Fi.

**SSH:**

```bash
ssh -i ~/mirobot_key root@192.168.8.1
```

**Совет:** после настройки Valetudo не забудь настроить **MQTT**, если планируешь прокидывать робота в Home Assistant.

## Сценарий подготовки к работе с Player (основной)

Этот сценарий в проекте — **основной** bring-up для отладки через штатный **`player`** (`:6665`): разогнать навигационный стек, затем выйти в состояние, удобное для `xiaomi_robot` (лидар, `playerc`, при необходимости Valetudo manual).
Подробный смысл шагов и таблица «зачем» — [PLAN.md §4.2.1](./PLAN.md#421-основной-сценарий-подготовки-зафиксирован-как-канон).

**Чеклист (на роботе / по SSH):**

1. Убедись, что **`RoboController` не** мешает (не тот экземпляр, с которым будешь работать, или останови лишние).
2. Запусти **`/opt/rockrobo/cleaner/bin/RoboController`**.
3. **Нажми Home** на корпусе — робот **поедет** (поиск дока / навигация).
4. Когда **идёт движение**, **останови** `RoboController` (с консоли: `Ctrl-C` или `kill` с сигналом, которым прерывают foreground-процесс).
5. **Подними робота** (сорви с пола) — **прерви** навигацию физически; ориентир: слышен **только** мотор **лидара** (LDS крутится).
6. Проверь [health-check `player`](#health-check-player-перед-xiaomi_robot) и **iptables** (часто `DROP` на `6665`); затем запускай `xiaomi_robot` на `127.0.0.1:6665`.

**Не автоматизируется полностью** с ПК: шаги **Home** и **поднятие** требуют рук и визуального подтверждения.

## Health-check `player` перед `xiaomi_robot`

Если клиент `xiaomi_robot` не может подключиться к `player` (`:6665`), сначала проверь
системный стек на роботе одной командой.

```bash
cd xiaomi_vacuum
./scripts/healthcheck_player.sh 192.168.0.137
```

Скрипт проверяет:

- процессы `player`/`RoboController`/`WatchDoge`/`AppProxy`;
- `LISTEN` на порту `6665`;
- TCP-пробу `nc -vz -w 2 127.0.0.1 6665`;
- признаки IPC-ошибок в логах (`Failed to open pipe`, `Unable to read packet from pipe`, `player exit`).

Опционально можно сразу сделать smoke-тест бинарника:

```bash
RUN_XIAOMI_ROBOT=1 XIAOMI_ROBOT_LOOPS=3 ./scripts/healthcheck_player.sh 192.168.0.137
```

Если видишь паттерн `LISTEN + nc timeout + pipe errors`, значит `player`-стек на роботе
деградировал: перезапускай полный штатный стек робота, а не только `xiaomi_robot`.

Отдельный частый кейс: порт `6665` режется firewall (`iptables INPUT DROP tcp dpt:6665`).
Проверка/исправление:

```bash
ssh root@ROBOT_IP "iptables -L INPUT -n --line-numbers | grep 6665 || true"
ssh root@ROBOT_IP "while iptables -C INPUT -p tcp --dport 6665 -j DROP 2>/dev/null; do iptables -D INPUT -p tcp --dport 6665 -j DROP; done"
ssh root@ROBOT_IP "while iptables -C INPUT -p udp --dport 6665 -j DROP 2>/dev/null; do iptables -D INPUT -p udp --dport 6665 -j DROP; done"
ssh root@ROBOT_IP "nc -vz -w 2 127.0.0.1 6665"
```
